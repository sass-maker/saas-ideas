# ADR-001 — Single source of truth in `build.py`

- **Status:** Accepted
- **Date:** 2026-02 (consolidation commits `3898cf2`, `5a2bb03`, `d56bc31`)

## Context

The repo originally held many separate idea markdown files
(`sass-maker.md`, `ai-knowledge-app.md`, `code-reviewer.md`, weekly
snapshots, etc.) plus a long README. Scores were informal and scattered; the
same idea could appear in multiple places with different scores, and there was
no single sortable view.

## Decision

Consolidate every idea and its scores into one Python script, `scripts/build.py`,
as the single source of truth. The script fully regenerates `README.md` and the
data file (`site/ideas.json`, formerly `docs/ideas.json`) on every run. No
partial state, no database, no migration step.

## Consequences

- **Pro:** any score change is one diff in one file; the output is always
  reproducible; there is exactly one home for each idea.
- **Pro:** the script is stdlib-only Python and runs offline — no install step
  to inspect or rescore the catalog.
- **Con:** the script is long (~590 lines) because it embeds all idea text.
  This is accepted; splitting idea text into per-file markdown would reintroduce
  the scattered-source problem this ADR was meant to solve.
- **Con:** `README.md` is generated, so it must never be hand-edited —
  documented in the README itself and in [AGENTS.md](../../../AGENTS.md).

## Notes

The published `site/index.html` is intentionally **not** generated by `build.py`
— it is a static shell that reads `site/ideas.json` at runtime. This keeps the
build script focused on data, not HTML.
