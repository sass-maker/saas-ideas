# AGENTS.md

Agent bootloader for the `saas-ideas` repo. Read this first; link out for depth.

## What this repo is

A scored, sortable catalog of SaaS product ideas, filtered to tech-heavy
(`T >= 7`), solo-feasible bets targeting $5K MRR. The output is a static HTML
table deployed to Cloudflare Pages. It is a personal decision-support tool, not
a product for sale. Full context: [docs/product/overview.md](docs/product/overview.md).

## Source of truth

| Thing | Where | Edit? |
| --- | --- | --- |
| Ideas + scores + scoring logic | `scripts/build.py` | Yes — only here |
| Researched Starterstory descriptions | `data/starterstory_descriptions.json` | Yes |
| Published catalog (HTML, data, agent surfaces) | `site/` | Only `index.html` shell + agent surfaces; `ideas.json` is generated |
| Documentation (this knowledge system) | `docs/` | Yes |
| `README.md` | repo root | **No** — generated by `build.py` |

Never hand-edit `README.md` or `site/ideas.json`.

## Essential commands

```
python3 scripts/build.py        # rebuild README.md + site/ideas.json (offline, stdlib-only)
python3 scripts/check-docs.py   # validate docs/ links + frontmatter
npx blume dev                   # preview docs/ site (after npm install)
npx blume build                 # build docs/ to dist/
npx wrangler pages deploy ./site --project-name saas-ideas   # publish catalog
```

## Critical constraints

- **`build.py` is the single source of truth.** Adding/rescoring an idea means
  editing `build.py`, not the generated files. See
  [docs/development](docs/development/index.md).
- **`fun` and `money` must be computed AFTER `F_feas` and `customer` are
  stamped.** Reordering the stamp/derive loops in `build.py` breaks scoring
  (commit `a58a35d` fixed this once). See
  [ADR-002](docs/architecture/decisions/adr-002-derived-fun-money-scores.md).
- **`MIN_T = 7` is inlined as `7` in the filter** because the constant is
  defined later in the script. If you move the constant, update the filter
  (commit `a21320d`). See
  [ADR-003](docs/architecture/decisions/adr-003-tech-heavy-filter.md).
- **`docs/` is the knowledge system; `site/` is the published catalog.**
  Do not deploy `docs/` as the catalog. See
  [ADR-007](docs/architecture/decisions/adr-007-relocate-site-reclaim-docs.md).
- **Blume is presentation only.** Markdown in `docs/` is the source of truth;
  `blume.config.ts` only renders it. Do not put catalog data in `docs/`.
- **Do not commit** `dist/`, `.blume/`, `node_modules/`, `.wrangler/`.
- **Do not** edit secrets, `.env`, SSH keys, cloud creds, or production configs.
- **Do not** push, deploy, run migrations, or open PRs without explicit user
  approval. Make local changes and leave them for human review.

## Documentation maintenance rules

1. Markdown in `docs/` is the source of truth for "why"; code is the source of
   truth for "what". Do not duplicate facts that are easily discoverable from
   code.
2. One home per fact. If a fact moves, update all links; do not leave two homes.
3. When a scoring formula, filter, or inclusion rule changes, add an ADR in
   [docs/architecture/decisions/](docs/architecture/decisions/) and update
   [scoring.md](docs/product/scoring.md) if relevant.
4. When an idea is investigated and rejected, record it under
   [failed approaches](docs/knowledge/failed-approaches/index.md) so it is not
   re-investigated from scratch.
5. Run `python3 scripts/check-docs.py` before committing doc changes. CI runs
   it on push.
6. Keep pages focused (target 150-300 lines). Split rather than grow a
   catch-all page.
7. Mark unresolved questions explicitly (see [STATUS.md](STATUS.md)) — do not
   invent information.
8. Do not create empty folders or placeholder docs.
